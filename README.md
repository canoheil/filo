# فیلو (Filo) — دستیار هوشمند تلگرام

باتی که هر کاربر آن را از **Settings → Profile/Account → Chat Automation** به اکانت خودش وصل می‌کند تا از طرف او به پیام‌های خصوصی جواب بدهد — با پرسونای کاملاً شخصی‌سازی‌شده (هم برای کسب‌وکار، هم استفادهٔ شخصی). موتور: **Gemma 4** روی Google AI Studio (فعلاً کلید مشترک رایگان — سقف آگاهانهٔ ۳۰ جواب/روز برای کاربران رایگان). پرداخت اولیه: **Telegram Stars**.

> وضعیت: اسکلت عملیاتی v0.1 — onboarding، تنظیمات پرسونا، حالت Draft/Auto، اتصال Business، quota روزانه، ایده‌ام‌پوتنسی.

## چرا اینطوری ساخته شده
- **MariaDB + SQLAlchemy async + Alembic** — هم‌داستان با sib و cPanel هلند.
- **Polling فعلاً** (الگوی واچ‌داگ + کرون یک‌دقیقه‌ای sib). هندلرها transport-agnostic هستند؛ مهاجرت آینده به webhook (مثلاً Cloudflare Workers) فقط با افزودن یک front ممکن است — شرطش بازنویسی به runtime مناسب است، نه تغییر منطق.
- **حریم خصوصی:** متن پیام‌ها ذخیره نمی‌شود؛ فقط metadata. در حالت Draft متن پیش‌نویس تا لحظهٔ تأیید/رد نگه داشته و بعدش purge می‌شود.
- **Draft-first (پیش‌فرض):** هیچ جوابی بدون تأیید صاحب‌حساب ارسال نمی‌شود تا /setauto on.

## راه‌اندازی (روی cPanel هلند)
```bash
git clone <this repo> && cd filo
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # BOT_TOKEN و DATABASE_URL و GEMINI_API_KEY را پر کن
.venv/bin/python bot.py
```
برای دائم بالا نگه داشتن: `deploy/watchdog.sh` را به کرون یک‌دقیقه‌ای و `deploy/backup_db.sh` را به کرون روزانه اضافه کن.

در BotFather: یک بات بساز و **Secretary Mode** (قبلاً Business Mode) را فعال کن؛ تلگرام کاربر باید ۱۲.۷+ باشد.

## دستورات
`/start` `/whoami` `/setname` `/setrole` `/settone` `/setinfo` `/setrules` `/setauto on|off` `/pause` `/resume` `/forget`

## قدم‌های بعدی (roadmap)
1. پرداخت Stars: `send_invoice` با واحد XTR؛ پلن Pro (سقف بالاتر + Auto mode) و Business (چند اتصال/RAG).
2. لایهٔ انتزاع مدل (swap Gemma ↔ Gemini ↔ self-host) + BYOK برای کاربران حرفه‌ای.
3. حافظهٔ گفتگو (اختیاری، opt-in) — فعلاً آگاهانهٔ stateless.
4. داشبورد Mini App (سؤالات پرتکرار، تعداد جواب) + تمپلیت‌های آماده (فروشگاه/آرایشگاه/کلینیک).
5. تست‌های یکپارچهٔ business_message با mock تلگرام.

## مدیریت schema و دیپلوی نسخه‌های جدید

**قبل از تغییر دیتابیس:** بات و کرون watchdog را متوقف و از دیتابیس بکاپ قابل‌بازیابی بگیرید.
اسکریپت `deploy/backup_db.sh` فعلاً فقط راهنماست و بکاپ واقعی نمی‌گیرد.
دستورات زیر را از ریشهٔ پروژه با پایتون محیط مجازی اجرا کنید
(روی cPanel: `$HOME/virtualenv/filo/3.11/bin/python3`).

### دیتابیس خالی
قبل از اولین اجرای بات:
```bash
python -m alembic upgrade head
python -m alembic current
```

### سروری که قبلاً بات را اجرا کرده است
بات قبلی جدول‌ها را با `create_all` ساخته؛ **مستقیماً `upgrade head` اجرا نکنید**.
اول schema موجود را با `database/models.py` و migration `0001_initial` تطبیق دهید
(ستون‌ها، نوع‌ها، nullable، کلیدهای خارجی، unique و indexها).
فقط اگر همهٔ چهار جدول با schema اولیه یکسان‌اند:
```bash
python -m alembic stamp 0001_initial
python -m alembic check
python -m alembic current
```
`stamp` جدول نمی‌سازد و schema را اعتبارسنجی نمی‌کند؛ اگر `check` اختلاف نشان داد،
بات را روشن نکنید و اختلاف را بررسی کنید. دیتابیس ناقص یا متفاوت را کورکورانه stamp نکنید.
`downgrade base` جدول‌ها و داده‌ها را حذف می‌کند؛ روی دیتابیس واقعی اجرا نکنید.
فعلاً `init_db/create_all` برای سازگاری باقی مانده، ولی schema موجود را ارتقا نمی‌دهد؛
تغییرهای بعدی schema باید از طریق Alembic انجام شوند.

### حریم خصوصی و سهمیه
- خطای AI فقط کد امن برمی‌گرداند؛ بدنهٔ پاسخ سرویس و متن exception در لاگ برنامه نوشته نمی‌شود.
- درخواست ناموفق AI هم یک رزرو سهمیه مصرف می‌کند؛ retry داخلی آن رزرو اضافه نمی‌گیرد.
- متن پیش‌نویس‌های blocked/uncertain/sending ممکن است برای بررسی دستی باقی بماند؛
  ابزار بازیابی و انقضای خودکار هنوز پیاده نشده است.

### بررسی پیش‌نویس‌ها و تست سرور
`/drafts` در چت خصوصی، آخرین ۲۰ پیش‌نویس بازِ متعلق به کاربر را نشان می‌دهد.
فقط موارد در انتظار تأیید دکمه دارند؛ sending/blocked/uncertain خودکار دوباره ارسال نمی‌شوند.
پاسخ خودکار هم قبل از ارسال ثبت و از همین کنترل اتصال و مدیریت خطا عبور می‌کند.
چک‌لیست اجرای آزمایشی: [تست سرور](docs/server-smoke-test.md).

### رفع تبدیل فارسی به علامت سؤال در دیتابیس latin1
اگر ستون‌های `personas` یا `ai_message_log` با latin1 ساخته شده‌اند، migration
`0002_unicode_storage` آن‌ها را به utf8mb4 تبدیل می‌کند. قبل از اجرا بکاپ واقعی بگیرید،
بات/کرون را متوقف کنید و [راهنمای تعمیر Unicode](docs/unicode-storage-repair.md) را بخوانید.
متن‌هایی که قبلاً به `?` تبدیل شده‌اند بازیابی نمی‌شوند و باید دوباره وارد شوند.

## منوی دکمه‌ای
با `/start` یا `/menu` داشبورد را باز کنید؛ ویرایش شخصیت، اطلاعات، قوانین، کنترل پاسخ‌دهی،
پیش‌نویس‌ها و حریم خصوصی با دکمه در دسترس‌اند. برای لغو ویرایش `/cancel` را بزنید.
[طراحی و چک‌لیست تست منوی Inline](docs/inline-menu.md). کامندهای پیشرفته همچنان پشتیبانی می‌شوند.


## نام محصول
نام محصول «فیلو» (Filo) است. نام و نقش دستیار هر کاربر همچنان قابل تنظیم‌اند؛
تغییر برند، نام‌های قبلی و شخصی‌سازی‌شده را بازنویسی نمی‌کند. نام پیش‌فرض دستیارهای جدید «فیلو» است.
نام نمایشی، توضیحات و تصویر پروفایل خود بات باید جداگانه در BotFather به‌روزرسانی شوند؛
تغییر متن‌های کد، نام یا یوزرنیم ثبت‌شده در تلگرام را تغییر نمی‌دهد.

## راه‌اندازی هدایت‌شده
دکمهٔ «آماده‌سازی فیلو» چک‌لیست آمادگی و مسیر قابل‌ادامهٔ تنظیم شخصیت، اطلاعات، آزمایش و
بررسی اتصال را باز می‌کند. تنظیمات قبلی بدون انتخاب کاربر بازنویسی نمی‌شوند.
این قابلیت به migration `0003_setup_progress` نیاز دارد؛ قبل از restart، `alembic upgrade head`
را با رعایت بکاپ و وضعیت revision فعلی اجرا کنید. [راهنمای راه‌اندازی](docs/guided-setup.md).

## حافظهٔ کوتاه گفتگو (اختیاری)
از منوی «حافظهٔ کوتاه گفتگو» با رضایت مالک فعال می‌شود: حداکثر ۱۲ پیام اخیر هر گفتگو،
موقتاً در RAM و تا ۱۵ دقیقه بی‌فعالیتی. متن تاریخچه در دیتابیس ذخیره نمی‌شود؛ سابقه همراه پیام جدید
به AI ارسال می‌شود. پیش‌نویس ارسال‌نشده جزو پاسخ‌های سابقه نیست. امکان خاموش‌کردن و پاک‌کردن وجود دارد.
این قابلیت تاریخچهٔ قبلی تلگرام را واکشی نمی‌کند و پس از restart متن‌ها پاک می‌شوند.
**migration جدید: `0004_recent_context`**. [جزئیات و تست](docs/recent-context.md).

## ویرایش پیش‌نویس
دکمهٔ «✏️ ویرایش» امکان تغییر متن قبل از ارسال را می‌دهد. نسخهٔ اصلاح‌شده همچنان به تأیید نهایی
نیاز دارد و دکمهٔ نسخهٔ قبلی معتبر نیست. این نسخه به migration `0005_draft_revision` نیاز دارد.
[راهنمای ویرایش و تست](docs/draft-editing.md).

## چرخهٔ عمر پیش‌نویس
مهلت ارسال/ویرایش پیش‌فرض ۶۰ دقیقه است؛ متن پیش‌نویس منقضی پاک می‌شود. متن موارد خطادار
حداکثر تا ۲۴ ساعت از ساخت نگه داشته و در اجرای دوره‌ای پاک می‌شود. ویرایش مهلت را تمدید نمی‌کند.
رد گروهی و بستن مورد خطادار، تأیید جداگانه دارند و ارسال مجدد انجام نمی‌دهند.
این شاخه به migrationهای `0005_draft_revision` و `0006_draft_lifecycle_index` نیاز دارد.
[سیاست و راهنمای استقرار](docs/draft-lifecycle.md).

## کنترل گفتگو و تحویل به مالک
از «💬 کنترل گفتگوها» می‌توانید پاسخ‌دهی یک گفتگوی مشخص را مکث/ادامه کنید. تحویل خودکار پس از
پیام مالک، اختیاری و پیش‌فرض خاموش است (۱۵، ۳۰ یا ۶۰ دقیقه). مکث کلی و سهمیه مستقل می‌مانند.
این نسخه به migration `0007_chat_controls` نیاز دارد. [جزئیات و تست](docs/chat-controls.md).
