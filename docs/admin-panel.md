# پنل مدیریت — گام اول

## راه‌اندازی
در `.env` شناسهٔ **عددی حساب شخصی** ادمین را وارد کنید (نه username و نه شناسهٔ بات):
```dotenv
ADMIN_IDS=123456789
# چند مدیر: ADMIN_IDS=123456789,987654321
```
ورودی نامعتبر مانع startup می‌شود. پس از تغییر مدیران، restart لازم است.
فقط در گفت‌وگوی خصوصی `/admin` بزنید. هر پیام، ورودی و callback مدیریتی مجدداً کنترل دسترسی دارد.
پنل برای مدیر بدون شرط عضویت باز است تا بتواند خرابی تنظیمات را اصلاح کند؛ این استثنا به
/start یا استفادهٔ عادی از محصول تعمیم ندارد. متن‌های عضویت همچنان جمع «کانال‌ها» هستند.

## استقرار
از دیتابیس backup بگیرید، بات و watchdog را متوقف کنید و با محیط مجازی واقعی سرور اجرا کنید:
```sh
$HOME/virtualenv/filo/3.11/bin/python3 -m alembic upgrade head
```
این شاخه شامل migration قبلی `0009_usage_health` و migration جدید `0010_admin_channels` است.
هر سه جدول جدید charset/collation صریح utf8mb4/utf8mb4_unicode_ci دارند. DDL در MySQL ممکن است
implicit commit داشته باشد. سپس بات/watchdog را راه بیندازید. هم‌زمان فقط یک polling process اجرا شود.

در اولین startup، SUPPORT_CHANNEL فعلی یک بار وارد DB می‌شود؛ حتی فهرست خالی هم نشانگر راه‌اندازی
ثبت می‌کند. از این پس **DB مرجع شرط عضویت است** و ویرایش/خالی‌کردن SUPPORT_CHANNEL آن را تغییر نمی‌دهد.
حذف از پنل با restart برنمی‌گردد. بعد از انتقال می‌توانید هر دو SUPPORT_CHANNEL و
SUPPORT_CHANNEL_JOIN_URL را خالی کنید؛ تنظیم قدیمیِ نامعتبر همچنان در startup رد می‌شود.
در صورت خطای DB، شرط عضویت fail-closed است؛ از env به‌عنوان fallback استفاده نمی‌شود.

## مدیریت کانال‌ها
از «مدیریت کانال‌ها» عمومی را با @username یا URL عمومی وارد کنید. برای خصوصی:
```text
-1001234567890 https://t.me/+YOUR_INVITE_TOKEN
```
پیش از افزودن و فعال‌کردن، نوع مقصد و ادمین‌بودن بات از Telegram بررسی می‌شود. بات باید از قبل
ادمین باشد. لینک خصوصی باید متعلق به همان شناسه و معتبر باشد؛ API تطابق لینک دعوت را تضمین نمی‌کند.
هر مورد جدید فعال است؛ قبل از فرستادن اطلاعات، مطمئن شوید قصد اعمال شرط را دارید.
حداکثر ۱۰ مورد ثبت می‌شود (فعال و غیرفعال) تا طول پیام و زمان API محدود بماند.
برای تغییر لینک، مورد قبلی را حذف و دوباره اضافه کنید. غیرفعال‌کردن، تنظیم را نگه می‌دارد؛ حذف تأیید جدا دارد.
همهٔ موارد فعال الزامی‌اند. حذف آخرین مورد یا غیرفعال‌کردن همه، شرط را خاموش می‌کند.

نوشتن‌ها با قفل ردیف سیاست سری می‌شوند، دکمه‌ها version دارند و کلیک قدیمی تغییر جدید را بازنویسی نمی‌کند.
هر تغییر revision سیاست را بالا می‌برد؛ بررسی بعدی کاربر از کش مثبت سیاست قبلی استفاده نمی‌کند، حتی اگر
موردی غیرفعال و دوباره فعال شود. عملیات/درخواست شبکه‌ای که قبلاً شروع شده قابل پس‌گرفتن نیست.
برای عضویت تحت سیاست ثابت، همان TTL حداکثر ۳۰ ثانیه پابرجاست؛ /start و بررسی دوباره تازه‌اند.

## داشبورد و ثبت عملیات
فعلاً شمار کاربران ثبت‌شده و اتصال‌های فعال **ثبت‌شده در DB** نمایش داده می‌شود؛ این اعداد به معنی
آنلاین‌بودن کاربران یا تأیید زندهٔ سلامت اتصال نیستند. مصرف سراسری در این گام اضافه نشده؛ ارسال سراسری اکنون در [broadcast.md](broadcast.md) مستند شده است.
افزودن/فعال/غیرفعال/حذف با شناسهٔ مدیر، عمل، شناسهٔ داخلی مورد و زمان UTC ثبت می‌شود؛ نه متن خصوصی و نه لینک دعوت.
این audit مدیریتی به حساب کاربر FK ندارد و /forget آن را حذف نمی‌کند؛ باید در سیاست نگهداری اپراتور لحاظ شود.
لاگ خطا فقط نوع استثنا دارد. پنل ممکن است لینک خصوصی ذخیره کند؛ دسترسی و backup دیتابیس را محدود نگه دارید.

## آزمون واقعی پس از استقرار
- مدیر /admin را ببیند؛ حساب غیرمجاز و پیام گروهی نتوانند تغییر ایجاد کنند.
- مدیر غیرعضو بتواند تنظیمات را اصلاح کند، ولی /start او شرط محصول را دور نزند.
- عمومی و خصوصی را با بات ادمین اضافه کنید؛ گروه و بات غیرادمین رد شوند.
- با افزودن اسپانسر، کاربر عضو پشتیبانی ولی غیرعضو اسپانسر مسدود شود و هر دو دکمه را ببیند.
- غیرفعال/فعال و حذف را تست کنید؛ دکمهٔ قدیمی نتواند تغییر را بازنویسی کند.
- پس از حذف و restart مورد برنگردد؛ حذف آخرین مورد شرط را خاموش کند.
- در خطای API/DB پیام فنی ظاهر شود، نه ادعای قطعی عدم عضویت؛ /admin برای اصلاح همچنان قابل دسترسی باشد.
- /forget بدون عضویت همچنان کار کند. مخاطبان بیزینسی دعوت دریافت نکنند.

Rollback این migration فهرست و audit را حذف می‌کند؛ کد قدیمی دوباره از env پیروی می‌کند و ممکن است
شرط متفاوتی اعمال کند. قبل از rollback سرویس را متوقف و تنظیم env موردنظر را صریح آماده کنید.
تست واقعی Telegram/MariaDB و deployment در محیط توسعه انجام نشده است.
