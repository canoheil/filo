# شرط عضویت در کانال‌ها

## تنظیم محیط
برای یک کانال عمومی، یکی از دو قالب زیر در `.env` کافی است:
```dotenv
SUPPORT_CHANNEL=@filo_support
# یا SUPPORT_CHANNEL=https://t.me/filo_support
SUPPORT_CHANNEL_JOIN_URL=
```
نام نمونه است؛ آدرس واقعی خودتان را جایگزین کنید. BotFather یا نام نمایشی کانال، شناسهٔ بررسی عضویت نیست.
بات باید در کانال تنظیم‌شده **ادمین** باشد. مجوز ارسال پست برای این بررسی لازم نیست؛
عضویت مدیر برای قابل اتکا بودن getChatMember کاربران دیگر لازم است.

برای کانال خصوصی، لینک دعوت به‌تنهایی شناسهٔ قابل استفادهٔ getChatMember نیست:
```dotenv
SUPPORT_CHANNEL=-1001234567890
SUPPORT_CHANNEL_JOIN_URL=https://t.me/+YOUR_INVITE_TOKEN
```
شناسهٔ عددی واقعی و لینک معتبر متعلق به همان کانال را تنظیم کنید. کد نمی‌تواند فقط از لینک خصوصی
شناسه را استخراج کند یا ثابت کند لینک دعوت متعلق به شناسهٔ درج‌شده است؛ مسئولیت تطبیق با مدیر است.
لینک منقضی/لغوشده را خودکار عوض نمی‌کنیم. ورودی‌های نامعتبر یا URL خارج از https://t.me در startup رد می‌شوند.
خالی‌بودن هر دو متغیر یعنی این شرط خاموش است. تنظیم لینک بدون SUPPORT_CHANNEL خطاست.
پس از تغییر `.env` بات باید restart شود؛ تنظیمات cache می‌شوند. توکن یا فایل `.env` را commit نکنید.

## تجربهٔ کاربر
متن الزام دقیقاً جمع است، حتی با یک مورد:
> برای ادامهٔ استفاده از فیلو، باید عضو کانال‌های زیر شوی.

زیر پیام، دکمهٔ «عضویت در کانال‌ها» و «عضو شدم؛ بررسی دوباره» قرار دارد. دکمهٔ ورود لینک را باز
می‌کند و callback دوباره از Telegram بررسی می‌کند؛ صرف کلیک‌کردن اثبات عضویت نیست.
درخواست عضویت pending تا پذیرش مدیر، عضویت محسوب نمی‌شود. پس از تأیید، داشبورد باز می‌شود.
همین بررسی روی /start اجرا می‌شود. پیام‌های خصوصی/منوها/ویرایش‌ها/دکمه‌های قدیمی نیز کنترل دارند؛
کاربر با /menu یا دکمهٔ پیش‌نویس نمی‌تواند شرط را دور بزند. ورودی نیمه‌تمام در صورت رد دسترسی لغو می‌شود.

وضعیت member/administrator/creator عضو است؛ restricted فقط با is_member=True عضو محسوب می‌شود.
left/kicked یا restricted غیرعضو، شرط را برآورده نمی‌کند. نقش خود بات ابتدا بررسی می‌شود.
ادمین‌نبودن بات، خطای شبکه/Telegram، محدودیت نرخ یا وضعیت ناشناخته **خطای بررسی** است، نه اثبات
عضو نبودن کاربر. پیام خطای فنی جداگانه با واژهٔ «کانال‌ها» نشان داده می‌شود و دسترسی تا تأیید بسته است.
متن خطای خام یا لینک خصوصی در لاگ برنامه نوشته نمی‌شود؛ فقط نوع خطا/نبود مجوز ادمین ثبت می‌شود.

## حساب متصل، کش و حریم خصوصی
پیش از quota/AI و قبل از ارسال پیش‌نویس، عضویت **مالک اتصال** بررسی می‌شود؛ مخاطب دایرکت
ملزم به عضویت نیست و برایش پیام تبلیغ/دعوت ارسال نمی‌کنیم. در حالت عدم تأیید، AI و سهمیه مصرف
نمی‌شود. در ارسال پیش‌نویس ممکن است وضعیت blocked شود؛ پس از عضویت خودکار retry نمی‌شود.
پیام‌های ورودی ردشده برای بعد صف نمی‌شوند. کنترل مکث، تحویل به مالک، ساعت، quota و مجوز ارسال مستقل‌اند.

تأیید مثبت حداکثر ۳۰ ثانیه در RAM cache می‌شود (حداکثر ۱۰۲۴ کاربر، کلید شامل بات و تنظیم کانال‌هاست).
/start و callback بررسی دوباره همیشه تازه‌اند و cache قبلی همان کلید را کنار می‌گذارند؛
خطا و نتیجهٔ منفی cache نمی‌شوند. خروج از کانال یا برداشتن ادمین بات ممکن است برای درخواست معمولی
تا سقف TTL دیرتر اعمال شود؛ این محدودیت عمدی کاهش API است. هر تماس API حداکثر ۵ ثانیه timeout دارد.
تاریخچهٔ عضویت در DB ذخیره نمی‌شود. به Telegram فقط شناسهٔ کاربر/کانال برای بررسی داده می‌شود.

حریم خصوصی و مسیر /forget → تأیید حذف، بدون عضویت قابل دسترسی باقی می‌مانند؛
هیچ مدیر/پلن پولی استثنای خودکار برای استفاده از محصول ندارد. حذف داده‌ها تابع مالکیت و تأیید قبلی است.
دکمه‌های داخل گروه یا پیام غیرقابل دسترس هنگام فعال‌بودن شرط، محصول خصوصی را باز نمی‌کنند.

## استقرار و گسترش
این قابلیت به‌تنهایی ستون/جدول یا migration جدید ندارد. این شاخه همچنین فاز قبلی مصرف/سلامت و
migration `0009_usage_health` را دارد؛ اگر هنوز اعمال نشده، طبق docs/usage-health.md قبل از restart اجرا شود.
بات را در کانال ادمین، `.env` را تنظیم، وابستگی‌ها/کد را deploy و restart کنید. دسترسی API به Telegram لازم است.
ساختار داخلی بررسی، لیستی از کانال‌ها را می‌پذیرد، اما تنظیم محیط این مرحله فقط همان کانال پشتیبانی است.
چند کانال، پنل مدیریت یا منطق تجاری دیگری بدون مشخص‌شدن نیاز مرحلهٔ بعد اضافه نشده‌اند.

## تست سرور
1. با متغیرهای خالی رفتار قبلی حفظ شود؛ با تنظیم اشتباه startup خطای امن بدهد.
2. کاربر غیرعضو /start بزند: فقط پیام الزام جمع و دکمه‌های ورود/بررسی ببیند، نه داشبورد.
3. بدون عضویت «بررسی دوباره» بزند: داشبورد باز نشود.
4. عضو شود و دوباره بزند: داشبورد بدون نیاز به /start دوم باز شود.
5. member/admin/owner کانال عبور کنند؛ درخواست pending و حساب حذف‌شده از کانال عبور نکنند.
6. ادمین بات را بردارید یا API را موقتاً قطع کنید: پیام فنی بدهد، نه ادعای قطعی عضو نبودن.
7. پس از خروج از کانال، /start فوراً کنترل تازه کند؛ callback قدیمی و /menu راه دورزدن نباشند.
8. در حساب متصل، عضویت صاحب حساب بررسی شود و مخاطب دایرکت پیام دعوت نگیرد.
9. بدون عضویت هم /forget و تأیید حذف کار کنند؛ رد دسترسی نباید مانع پاک‌کردن داده شود.
10. کانال خصوصی را با ID و لینک صحیح و عمومی را با @username تست کنید.

تست‌های محلی statusها، خطا، cache، configuration، middleware/dispatcher، بررسی مالک در business،
ارسال نهایی و حذف داده را پوشش می‌دهند. کانال واقعی و Telegram در این محیط تست نشده‌اند.
